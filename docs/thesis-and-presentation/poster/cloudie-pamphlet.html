The problem

"Clean" today is not
clean forever

Cloud storage is where people keep their most important files, and where malware travels with them.

1
New and disguised malware slips past scanners

Signatures only know files someone has already reported. A macro hides in a Word file; a program is named invoice.pdf.exe.

2
Files are scanned only once

If a stored file is recognised as malware next week, nobody tells the owner.

3
Stored files and logs can be read or changed

Unencrypted files leak in one breach, and an editable activity log cannot prove what happened.

A file uploaded "clean" on Monday can be recognised as malware on Friday. Cloudie keeps checking.

How it works

Five steps for
every file

UploadAny file, from any browser or phone
ScanVirusTotal (~70 engines), structure checks, AI for PDFs
EncryptAES-256 with its own key for each file
StoreYou keep the key as text, QR or key file
Re-checkAsked again after upload, using only the file's fingerprint
CLEANEncrypted and stored
SUSPICIOUSStored, tagged with the reason
MALICIOUSBlocked, never stored

What makes it different

Four layers of
protection

Layered Malware Detection

VirusTotal first. Rule-based checks catch macros in macro-free files, zip-slip paths and fake extensions. A Random Forest model reads 32 features of each PDF.

AES-256 & QR Key

Each file has its own key. Cloudie stores only a SHA-256 fingerprint of it, so a database leak alone opens no file.

Retroactive Re-checkNEW

If VirusTotal later recognises a stored file, Cloudie quarantines it and warns the owner, without the key and without decrypting it.

Tamper-Evident Audit

Every action is sealed in an HMAC-SHA256 hash chain. Edit one row and the page shows "Tampering detected".
